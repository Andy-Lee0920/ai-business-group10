# Spec: search-bar

## 목적 (Why & Who)

타겟 및 문제: 누가 어떤 불편함을 느껴서 이걸 만드나요?
타겟: 서비스 내 콘텐츠가 많아져서 원하는 정보를 일일이 스크롤해서 찾기 힘든 모든 유저.  .

문제: 현재는 카테고리 분류나 정렬 기능이 부족해, 특정 키워드와 관련된 게시물을 찾는 데 시간이 너무 오래 걸립니다. 유저의 이탈을 막기 위해 '즉각적인 정보 접근성'이 필요합니다.

## 핵심 기능 (Scope)

P0 (필수): 데모를 위해 '반드시' 작동해야 하는 것
:텍스트 입력창 및 검색 아이콘 UI.
입력한 키워드가 제목에 포함된 결과 필터링.

검색 결과 리스트 표시.
P1/P2 (제외): 이번에 안 하거나 나중에 할 것 (간략히)
P1: 검색어 자동 완성(Autocomplete), 검색 기록 저장.
P2: 본문 내용까지 포함한 풀텍스트 검색, 다국어(영어/일어) 지원, 필터링 옵션(날짜별, 카테고리별).

## 유저 경험 (UX & AI)

사용자 흐름: 유저가 들어와서 보게 될 핵심 단계 (1 → 2 → 3)
입력: 유저가 메인 상단 검색창에 키워드(한글)를 입력하고 'Enter' 또는 '돋보기 아이콘' 클릭.
결과 표시: 키워드가 포함된 결과물이 최신순(내림차순)으로 리스트업됨. (결과가 없을 경우 "검색 결과가 없습니다" 메시지 노출)
이동: 결과 목록 중 하나를 클릭하면 해당 상세 페이지로 즉시 라우팅.

## 데모 합격 기준 (Success)

최소 요건: 시연 때 "이게 되면 성공이다"라고 부를 수 있는 기준
정확성: DB에 존재하는 제목 키워드 입력 시 해당 항목이 결과에 반드시 포함되어야 함.
정렬: 검색된 리스트가 뒤섞이지 않고 최신순으로 잘 정렬되어야 함.
연결: 검색 결과 클릭 시 404 에러 없이 정확한 상세 페이지로 이동해야 함.

## 확인 사항 (Validation)

어떻게 테스트할 예정인가요?
단위 테스트: 1글자 검색, 긴 문장 검색, 특수문자 검색 시 오류 여부 확인.
통합 테스트: 실제 데이터 셋을 넣고 검색 속도가 1초 이내로 나오는지 확인.
사용성 체크: 검색창의 위치가 모바일/데스크톱 환경에서 직관적으로 보이는지 확인.
