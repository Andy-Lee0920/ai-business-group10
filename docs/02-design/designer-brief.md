# Designer Brief — Fevio [페비오] SLC

## 디자인 방향 한 줄

**병원 앱처럼 차갑게 보이지 않되, 의료 정보를 다루는 만큼 가볍거나 장난스럽게 보이지 않는 따뜻한 실행 도구.**

Fevio [페비오]는 병원 진료 내용을 대신 판단하는 앱이 아니라, 사용자가 병원에서 들은 내용을 안전하게 정리해서 오늘 할 일과 파트너가 도울 일을 나누는 모바일 웹앱이다.

---

## 지향할 것

### 1. 따뜻한 모바일 웹앱

- 크림/세이지/라벤더 계열
- 부드러운 카드
- 여백 충분히
- 큰 터치 영역
- 모바일 웹이지만 앱처럼 안정적인 느낌

### 2. 오늘 할 일 중심

홈에서 바로 보여야 하는 것은 “모든 정보”가 아니라 **오늘 제일 먼저 해야 할 일**이다.

- 다음 액션이 명확해야 함
- 정보 나열보다 우선순위가 중요함
- 사용자가 홈만 보고 실행 순서를 이해해야 함

### 3. 확인 가능한 실행감

사용자는 불확실한 병원 메모를 그대로 행동으로 실행하면 안 된다. “확정 전/확정 후”가 분명해야 한다.

중요한 버튼/상태 예시:

- 확인했어요
- 파트너에게 공유
- 병원에 다시 물어볼 항목
- 완료
- 아직 확정 전

### 4. 남편/파트너 시점도 따뜻하게

파트너 화면은 감시나 지시처럼 보이면 안 된다.

좋은 톤:

```text
오늘 이렇게 도와줄 수 있어요.
```

피해야 할 톤:

```text
당신이 이걸 해야 합니다.
왜 아직 확인하지 않았나요?
```

파트너에게는 모든 의료 정보가 아니라 **오늘 도울 행동**만 간결하게 보여준다.

### 5. 불안을 낮추는 문구

화면 문구는 사용자가 실수할까 봐 긴장하는 상태를 낮춰야 한다.

예시:

- 잘 모르겠는 내용도 그대로 적어도 괜찮아요.
- 확정 전에는 할 일로 표시되지 않아요.
- 의료 판단은 병원에 확인해 주세요.
- 파트너에게는 필요한 행동만 공유돼요.

## 피해야 할 것

### 1. 너무 병원 EMR/차트처럼 보이는 UI

피해야 할 느낌:

- 차가운 파랑/회색 위주
- 테이블/리스트 과다
- 의료기기 대시보드 느낌
- 병원 내부 시스템 같은 화면

이 앱은 병원 업무 시스템이 아니라 사용자의 치료 생활을 돕는 실행 도구다.

### 2. 임신/출산 앱처럼 과하게 핑크·베이비 톤

난임 치료 사용자는 감정적으로 민감할 수 있다.

주의할 요소:

- 과한 핑크
- 아기/축하/희망을 직접적으로 강요하는 이미지
- “곧 좋은 소식”처럼 결과를 암시하는 문구

따뜻함은 필요하지만, 결과를 낙관하거나 감정을 강요하면 안 된다.

### 3. AI 앱처럼 보이는 것

이 제품은 AI가 판단하는 앱이 아니다. 사용자가 확인한 행동을 정리하는 앱이다.

피해야 할 요소:

- 반짝이
- 마법봉
- 자동진단 느낌
- “AI가 알아서 정리/판단”하는 인상

AI가 들어가더라도 P1 선택 기능이며, 수동 확인이 중심이다.

### 4. 위험/긴급을 남발하는 디자인

중요한 치료 행동은 놓치면 안 되지만, 화면이 사용자를 겁주면 안 된다.

- 빨간색 과사용 금지
- 모든 항목을 critical처럼 보이게 하지 않기
- 중요 표시는 명확하되 공포스럽지 않게
- warning은 soft coral 계열로 제한적으로 사용

### 5. 파트너에게 민감정보를 많이 보여주는 화면

파트너 화면은 action-only에 가깝게 설계한다.

보여주지 말아야 할 것:

- 원문 병원 메모 전체
- 감정 기록
- 개인 메모
- 불필요한 의료 세부사항
- 다른 날짜의 민감정보

보여줄 것:

- 오늘 도울 행동
- 시간
- 변경 여부
- 확인 버튼
- 물어볼게요 버튼

## 우선 디자인해야 할 핵심 화면 5개

### 1. Privacy Gate

목적:

- 민감정보 수집·이용 동의
- 파트너 공유 동의
- 의료 조언 아님 고지

디자인 기준:

- 차갑지 않지만 신뢰감 있게
- 체크/동의 항목이 명확하게
- 사용자가 무엇에 동의하는지 쉽게 이해해야 함

### 2. Onboarding Home

목적:

- 첫 로그인 후 아직 병원 메모가 없을 때 보여주는 홈
- routine day가 아니라 onboarding 상태

핵심 메시지:

```text
병원 메모를 넣어 오늘 할 일을 정리해보세요.
```

### 3. Post-Visit Capture

목적:

- 병원에서 들은 내용을 그대로 붙여넣거나 입력

필요 요소:

- 큰 textarea
- 붙여넣기 CTA
- 안심 문구
- “내용 나누기” CTA

좋은 문구 예시:

```text
잘 모르겠는 내용도 그대로 적어도 괜찮아요.
확정 전에는 할 일로 표시되지 않아요.
```

### 4. Manual Split Review

목적:

- 병원 메모를 줄 단위로 나누고 사용자가 직접 분류

4개 버튼:

- 내 할 일
- 파트너에게 공유
- 병원에 확인
- 제외

디자인 기준:

- 각 줄이 하나의 카드처럼 보일 것
- 선택 상태가 분명할 것
- “확정하기” 전까지 실행 항목이 아니라는 느낌이 있을 것

### 5. Partner Action View

목적:

- 파트너가 로그인 없이 링크로 오늘 도울 일만 보기

필요 요소:

- 오늘 도울 일
- 시간/상태
- 변경됨 배지
- 확인했어요
- 민지에게 물어볼게요

디자인 기준:

- 부담 낮게
- 감시받는 느낌 없이
- 원문 메모/민감정보 노출 없이

## 디자인 토큰 초안

```text
Primary: sage green
Background: warm cream
Accent: soft lavender
Warning: soft coral
Card: rounded, light shadow, high whitespace
Typography: Korean readability first
Touch target: mobile-first, large buttons
```

현재 참고 후보:

```text
Primary sage: #6F8F6E
Accent lavender: #B9AED6
Warm neutral/background: #F6F4F1
Warning coral: #E07A68
Card radius: around 16px
```

## 디자인 성공 질문

디자인 리뷰 때 아래 질문에 답할 수 있어야 한다.

1. 이 화면을 보고 사용자가 덜 불안해지는가?
2. 오늘 해야 할 일이 더 명확해지는가?
3. 파트너가 부담스럽지 않게 도울 수 있는가?
4. 의료 판단처럼 보이지 않는가?
5. 민감정보가 과하게 드러나지 않는가?

이 5개를 통과하면 SLC 방향에 맞는 디자인이다.
