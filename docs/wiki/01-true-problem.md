# Fevio가 해결하는 진짜 문제

> "핵심 문제는 정보 부족이 아니다. 병원 지시사항은 존재한다. 진짜 문제는 **정보 번역 격차 + 운영 과부하**다."
> — PRD v1.0 §2.2

## 표면적 문제 vs 진짜 문제

IVF 환자는 정보가 없어서 고통받는 것이 아니다. 병원에서 지시사항을 받는다. 하지만 그 지시사항을 다음 형태로 변환하는 **번역 작업 전체가 한 사람에게 집중**된다.

| 번역 질문 | 현실 |
|---|---|
| 오늘 몇 시에 무엇을 해야 하는가 | 환자 혼자 기억·정리 |
| 어떤 항목은 병원에 다시 확인해야 하는가 | 환자 혼자 판단 |
| 파트너가 무엇을 도와야 하는가 | 환자가 귀가 후 설명 (손실 발생) |
| 어떤 행동은 완료되었는가 | 환자 혼자 추적 |
| 어떤 행동은 놓치면 안 되는가 | 환자 혼자 우선순위 결정 |

이 번역 부담이 실수, 스트레스, 부부 갈등, 감정 소진으로 이어진다.

## 세 가지 구체적 고통 (인터뷰 기반)

### 약 혼동 (인터뷰이 A)
처방받은 약이 여러 개인데 이름이 비슷하거나 생김새가 유사해 착각한다. 시술에 영향을 주는 주사를 잘못 이해하고 빠뜨린 경험이 있다. 타이밍을 놓치면 시술 자체가 취소될 수 있다.

### 부부 정보 비대칭 (인터뷰이 B)
파트너가 주사를 직접 놔줘야 하는데, 아내 혼자 병원에서 들은 내용을 귀가 후 전달하는 과정에서 정보 누락·왜곡이 발생한다. 파트너는 "뭘 어떻게 해야 하는지 모르겠다"는 혼란을 반복한다.

### 감정 소진 (인터뷰이 C)
정보 관리, 병원 일정, 주사 준비까지 모두 혼자 감당한다. "나만 고생하는 것 같아서 억울하다"는 감정이 누적된다. 이것은 단순 불편이 아니라 **보이지 않는 치료 운영 노동이 한 사람에게 집중**되어 있다는 신호다.

## Fevio의 해결 방식

Fevio는 이 문제를 "더 많은 설명"이나 "따뜻한 문장"으로 해결하지 않는다. 병원 안내를 **확인 가능한 실행 카드로 구조화**하고, 그 상태를 각 역할에 맞는 행동 UI로 번역한다.

```text
병원 지시 (messy text)
  → 후보 분류 (사용자 검토)
  → 사용자 확인 (Confirm)
  → 확정된 실행 카드
  → Care Day 기반 Dynamic Home
  → 파트너: 자신이 도울 일만 보는 projection
```

### 환자에게 필요한 것
- 기록, 확인, 입력, 공유 제어

### 파트너에게 필요한 것
- 준비, 동행, 관찰, 다음 행동 확인

같은 치료 상태라도 두 사람이 봐야 하는 화면은 달라야 한다.

## Fevio가 아닌 것

아래는 의도적으로 Fevio가 아닌 것들이다. 이 경계를 유지하는 이유가 있다.

| 아닌 것 | 이유 |
|---|---|
| 일정표·약 알림 앱 | 기존 앱으로 대체 가능, 차별점 없음 |
| 의료 판단·AI 추천 앱 | 의료기기 규제 리스크, 신뢰 손상 위험 |
| 환자 화면을 파트너에게 복사하는 공유 앱 | 민감 정보 노출, 역할 구분 불가 |
| 감정 일기 앱 | 핵심 가치(실행 운영)와 거리가 멀음 |
| 예쁜 화면만 보여주는 static mock demo | 실제 state transition 없으면 제품이 아님 |

## 판단 기준 질문

새로운 기능을 추가할 때 이 질문들을 통과해야 한다.

1. 이 기능은 **shared care state를 더 정확하게** 만드는가?
2. 이 기능은 **환자의 통제권을 보존**하는가?
3. 이 기능은 **파트너에게 구체적 행동**을 주는가?
4. 이 기능은 **의료 판단 없이** 실행을 돕는가?
5. 이 기능은 **Vercel에서 실제로 보이고 조작**되는가?
